# logswap-sdk

TypeScript SDK for [Logswap](https://github.com/unimodularxyz/logswap) — typed wrappers over the
`LogswapManager` / `LogswapRouter` / `LogswapLens` surface.

**Status: phase 2 of `docs/app.md` — identity and derivation.** Reads and writes come next.

## What is here now

The two things the SDK must own because they are easy to get wrong by hand, and because getting them
wrong is silent:

| module | what it does |
|---|---|
| `src/keys.ts` | `PoolKey` and `poolId = keccak256(abi.encode(key))` — market identity |
| `src/ids.ts` | the ERC-6909 id namespace: position-class ids, token-claim ids, floor/cap packing |

Both are computed **offline** — no RPC, no deployment needed to address a market or a position.

## The derivation gate

Both derivations are **tier-1 frozen** (`docs/app.md`): `poolId` is the primary key of the entire
read model, and the position id is `(1 << 255) | (keccak256(poolId ‖ packed) >> 1)`, baked into every
client. If the TypeScript and the Solidity disagree, a client addresses the wrong pool or the wrong
position — silently, with funds behind it.

So `test/derivation.test.ts` checks against **vectors generated by the contract**, not by hand:

```bash
npm run vectors   # regenerate from the pinned contracts
npm test          # 45 vectors × poolId, positionId, pack/unpack round-trip
```

That makes it a genuine cross-implementation check. It is also verified non-vacuous: changing the
id derivation's shift by one bit fails all 45 position-id vectors.

A diff in `vectors/derivation-vectors.json` during an ordinary change means something is wrong — by
definition, a change there is a tier-1 event.

## The pipeline

```
logswap (forge)  ──►  contracts/abi/*.json  ──►  wagmi codegen  ──►  src/generated.ts
      ▲                                                                     │
  contracts.ref (pinned SHA)                                        the SDK wrappers
```

Nothing is ever hand-copied. `contracts.ref` pins the SHA; `npm run codegen` clones it, builds, and
regenerates; `tsc` is the drift gate, so a contract change that breaks the SDK is a red build rather
than a runtime surprise.

```bash
npm run contracts:sync   # clone/checkout the pinned contracts (gitignored)
npm run codegen          # sync + forge build + wagmi generate
npm run typecheck
npm test
```

## Conventions

- **The SDK hides the manager/router/lens split.** Which contract hosts which action is currently
  decided by EIP-170 headroom, not by design — so a future re-homing must be an SDK patch, not a
  breaking change for consumers.
- **Zero is not the default.** `phiMin` and `alpha` of `0n` resolve to their defaults at *read* time,
  so a key carrying `0n` and one carrying the resolved value are **different markets with different
  ids**. Always address a market by the key it was initialized with.
- **Split every ERC-6909 `Transfer` on bit 255.** Clear means a token claim, not a position; an
  indexer that ignores this reports phantom LP positions for market makers parking inventory.
